# 0057. 优惠券与会员模块

## 状态

Proposed（代码开发阶段）

## 背景

PRD 明确个人中心包含优惠券查看、会员中心查看/开通/续费，支付场景包含会员购买。现有订单金额试算已经预留 `discounts` 和 `discount_amount_minor`，但没有优惠券或会员业务模块。

## 决策

- `[DESIGN]` 新增 `backend/coupons` 和 `backend/memberships` 两个模块，采用模板/实例/购买/有效期/权益发放的可审计数据模型。
- `[DESIGN]` 优惠券当前只实现固定金额券，一单一张券，不支持多券叠加；订单退款不自动返还已使用优惠券，保留状态日志。
- `[DESIGN]` 会员购买不允许退款，已作为业务决策执行；支付失败或未支付不生成会员有效期。
- `[DESIGN]` 会员套餐价格、时长和权益通过不可变版本快照保存；截图中的套餐金额和时长只作为设计示例，不作为生产政策。
- `[DESIGN]` `Payment` 增加 `business_type/business_no`，兼容既有 `order_no`，支付回调按业务主体幂等确认订单或会员购买。
- `[DESIGN]` 会员权益先保存优先推荐、专属客服和会员优惠券的配置及发放记录；推荐算法、客服 SLA 和会员券生产规则另行确认。

## 后果

- 订单报价、创建、支付、取消和退款增加优惠券状态联动和金额快照。
- 会员购买支持余额、微信 App 和支付宝 App 发起支付；会员购买支付单禁止退款。
- 需要继续补齐正式套餐价格、会员券生产规则、推荐权重、账号注销留存和 OpenAPI/迁移/测试发布检查。
