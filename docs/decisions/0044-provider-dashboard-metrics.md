# ADR-0044：服务者数据看板指标与浏览事件

- 状态：已接受
- 日期：2026-11-14
- 决策人：项目负责人

## 背景

- 服务者需要工作台查看今日收入、今日订单、待处理订单和用户待评价订单。
- 数据看板还需要近 7/30 天浏览量、访客数、订单量、转化率、收入趋势和转化漏斗。

## 决策

- `[DESIGN]` 新增 `GET /api/v1/provider-dashboard/?range=7d|30d`，只允许已开通服务者访问。
- `[DESIGN]` 今日收入按今日生成的服务者收入记录统计；今日订单按今日创建订单统计。
- `[DESIGN]` 待评价订单只统计已完成、用户尚未评价且仍在评价期限内的订单，不统计服务者是否回复。
- `[DESIGN]` 浏览量/访客数和漏斗记录匿名 `PROVIDER_PROFILE_VIEW/SERVICE_VIEW/BOOKING_STARTED/PAYMENT_SUCCESS/ORDER_COMPLETED` 事件。
- `[DESIGN]` 前端通过 `X-Visitor-ID` 提供匿名访客标识，服务端只保存 HMAC 摘要和请求摘要，不保存明文 IP、设备号或手机号。
- `[DESIGN]` 转化率定义为完成订单数除以主页浏览量，按万分比返回；没有浏览数据时返回 `null`，不伪造转化率。

## 备选方案

- 直接用订单数估算浏览量：无法满足访客数、转化漏斗和较上期浏览变化。
- 在前端本地统计后上传：切换设备、清缓存和多端重复会造成统计不可复核。
- 立即建设数据仓库：当前数据量和阶段不需要，先使用可审计事件表和按日聚合。

## 影响

- `provider_analytics_events` 保存匿名浏览和转化事件。
- 服务者主页、服务详情、下单、支付、完成订单写入事件，业务事件按 `event_key` 幂等。
- 前端需要在公开主页和服务详情请求携带匿名 `X-Visitor-ID`。

## 风险与缓解

- 刷新页面会增加浏览量：浏览量按事件计数，访客数按匿名标识去重；未来可增加防抖/去重窗口。
- 访客标识被滥用：只接受短字符串并哈希保存，后续可增加限流和风控。
- 历史数据没有浏览事件：看板明确返回 `tracking_available=false`，不把订单数据伪装成浏览量。

## 验证

- 自动化测试覆盖今日指标、待评价口径、7/30 天范围、趋势、漏斗、权限和匿名事件。
- 运行迁移检查、完整 pytest、Ruff 和 OpenAPI。
