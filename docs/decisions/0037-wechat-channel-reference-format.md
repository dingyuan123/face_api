# 0037. 微信支付外部单号格式

## 状态

已确认并实施。

## 背景

- `[PRD]` 外部支付必须能够可靠关联内部支付单和退款单，并在回调后幂等落账。
- `[DESIGN]` 内部支付单和退款单使用 UUID，标准带连角线形式长度为 36 位。
- `[DESIGN]` 微信支付商户订单号最长为 32 位，直接提交 UUID 会返回 `PARAM_ERROR: 商户订单号错误`。

## 决策

- `[DESIGN]` 微信支付下单使用内部支付单 UUID 去掉连角线后的 32 位小写十六进制值作为 `out_trade_no`。
- `[DESIGN]` 微信退款使用相同规则生成 `out_trade_no` 和 `out_refund_no`，保持渠道内部单号可逆、唯一且符合长度限制。
- `[DESIGN]` 支付和退款通知仍以 UUID 解析渠道单号，因此无需新增映射字段或修改历史数据。
- `[DESIGN]` 支付宝继续使用标准 UUID 字符串作为外部单号；各渠道适配器负责转换渠道格式，业务层始终保存内部 UUID。

## 影响

- 微信下单、退款和回调测试必须覆盖 32 位渠道单号。
- 不改变支付金额、状态机、数据库幂等键或退款语义。
