# ADR 0017: 服务者图文动态管理与发布

- 状态：Accepted
- 日期：2026-10-30
- 范围：服务者图文动态、动态媒体、可选挂载服务和动态审核预留

## 背景

服务者需要在工作台管理动态并发布图文内容，首页和动态页需要后续消费已发布动态。视频、互动和推荐链路尚未完成。

## 决策

- `[PRD]` 动态包含文案、图片、标签、可见范围、推荐开关和可选挂载服务。
- `[DESIGN]` 第一阶段只支持 `IMAGE_TEXT`，动态图片 1 到 9 张，视频动态后续单独接入。
- `[DESIGN]` `MOMENT_REVIEW_MODE=IMMEDIATE` 时发布动作直接进入 `PUBLISHED`；`REVIEW_REQUIRED` 时进入 `PENDING`，管理员接口保留审核通过/拒绝。
- `[DESIGN]` 动态创建使用 `Idempotency-Key`，修改、发布、删除使用 `expected_version`，状态变化写入 `moment_events`。
- `[DESIGN]` 动态只引用本人 `MOMENT_IMAGE` 媒体；挂载服务可选且必须是本人 `ONLINE` 服务。
- `[DESIGN]` 公开接口只返回 `PUBLISHED + PUBLIC` 动态；`FOLLOWERS` 留到关注关系完成后开放。
- `[DESIGN]` 动态逻辑删除并保留事件；互动计数先作为只读字段，点赞、评论、分享、收藏和推荐后续实现。
- `[CONFIRM]` 动态审核策略、内容/图片审核、标签最终配置、视频转码播放、推荐权重和删除保留期限。

## 影响

- 服务者可以完成图文动态创建、发布、管理和公开查询。
- 首页可以逐步接入最近已发布动态图片。
- 视频和互动功能不应复用当前图片动态假设，需要单独设计视频媒体和互动数据。

## 验证

- `tests/test_moments.py` 覗盖发布、挂载服务、管理、删除、公开可见性和未来审核模式。
- pytest、Ruff、Django check、迁移检查和 OpenAPI 校验作为提交门槛。
