# ADR 0026: API 时间格式和后台审核退款

- 状态：Accepted
- 日期：2026-11-04
- 范围：API 时间输出、退款申请条件、后台审核和全额余额退款

## 背景

前端需要统一解析所有接口时间。订单取消退款目前直接执行，无法满足退款申请、后台审核、拒绝和失败重试要求。

## 决策

- `[DESIGN]` API 对外时间统一格式化为 `YYYY-MM-DD HH:mm:ss`，统一转换到 `Asia/Shanghai`；日期保持 `YYYY-MM-DD`，数据库继续保存 UTC。
- `[DESIGN]` 已支付订单满足“服务者未接单”或“预约开始前超过 6 小时”任一条件即可提交退款申请。
- `[DESIGN]` 服务开始后不允许申请或审核通过；同一订单同时只能有一个待审核退款申请。
- `[DESIGN]` 后台必须填写审核说明并使用申请版本进行同意或拒绝；拒绝不修改订单。
- `[DESIGN]` 同意退款时全额退回钱包余额，写不可变退款流水，更新支付和订单状态，释放全部预约小时单元。
- `[DESIGN]` 用户可以撤销待审核申请，后台可以重试退款失败申请；所有审核和状态变化进入订单日志。

## 影响

- API 输出层统一格式化所有递归响应时间，不修改数据库时间语义。
- 新增订单退款申请表、状态、版本和幂等约束。
- 未来优惠、部分退款、税费和真实支付退款必须扩展金额快照和渠道适配。
