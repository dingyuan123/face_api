# ADR-0006：第三方能力统一适配接口

- 状态：提议（待产品、采购和技术负责人确认）
- 日期：2026-10-27
- 决策人：待产品、采购和技术负责人确认 `[CONFIRM]`

## 背景

PRD 提及多家支付、实名、人脸、IM、内容审核、地图、存储和推送服务，厂商尚未确定。

## 决策

- `[DESIGN]` 业务模块只依赖 `integrations/contracts.py` 的稳定 Protocol/ABC 和 DTO。
- `[DESIGN]` 每个适配器实现请求、验签/结果、错误映射、重试、超时、幂等和审计字段。
- `[DESIGN]` 测试使用 fake/contract adapter；真实厂商接入前先完成沙箱和合同测试。
- `[DESIGN]` 第三方失败按业务分级降级：支付/实名/安全关键能力不能静默放行；内容/推送可进入队列重试。

## 备选方案

- 业务代码直接引用 SDK：接入快但绑定厂商、错误和重试逻辑散落，替换成本高。

## 影响

- 可替换厂商、可测试、可监控；需要维护统一 DTO、错误码和契约测试。

## 风险与缓解

- 风险：抽象过厚。缓解：只统一业务需要的稳定能力，不在第一阶段模拟所有厂商特性。
- 风险：回调差异。缓解：适配器保留原始回调、验签结果和第三方单号。

## 验证

- 每个适配器成功、失败、超时、重复、乱序、验签失败和重试测试。
