# ADR 0013: 媒体临时签名展示地址

- 状态：Accepted
- 日期：2026-10-29
- 范围：服务者申请图片展示和后续图片/视频资源访问

## 背景

当前 `content_url` 需要 Bearer Token，前端无法直接将地址放入图片标签。业务需要返回可直接加载的图片地址，同时不能把申请照片永久公开。

## 决策

- `[PRD]` `display_url` 默认有效期为 10 分钟，不严格绑定登录用户。
- `[DESIGN]` `display_url` 指向 HMAC 签名路由，签名覆盖媒体 ID、过期时间和密钥版本；签名错误返回 403，过期返回 410。
- `[DESIGN]` 同一媒体在有效期内重复请求业务接口时复用同一个展示地址，缓存仅作性能优化；访问图片本身不会生成新地址。
- `[DESIGN]` 展示地址由授权业务接口签发。当前申请人和管理员可获得申请照片地址，不能仅凭媒体 ID 获取地址。
- `[DESIGN]` `display_url_expires_at` 随媒体摘要返回，前端过期后重新请求业务接口。
- `[DESIGN]` 后续公开头像、生活照和动态图片必须经过审核/发布状态；视频返回封面和短期播放地址，长视频使用 HLS/CDN 签名；聊天媒体还校验订单或会话关系。
- `[DESIGN]` 后续 OSS/COS 使用同一响应字段和签名 URL 适配边界，不改变业务接口。
- `[CONFIRM]` 公共媒体审核、CDN 缓存、视频转码、聊天媒体和保留删除策略。

## 影响

- 前端可以直接使用 `display_url`，无需先下载 Blob。
- 展示地址是短期能力凭证，获得链接者可在有效期内访问，因此必须控制有效期和签发范围。
- 过期后前端必须刷新业务接口，不能长期缓存永久地址。

## 验证

- `tests/test_media_upload.py` 覆盖签名加载、篡改拒绝、过期拒绝和地址复用。
- `tests/test_provider_onboarding.py` 覆盖 `/api/v1/users/me/` 返回申请媒体摘要和展示地址。
- OpenAPI、Ruff、Django check、迁移检查和完整 pytest 作为提交门槛。
