# 0052. 账号注销条件、清理和审计

- 日期：2026-11-23
- 状态：已实施

## 背景

客户端已经实现账号注销全流程，需要后端固定校验订单、资金、服务发布和账号安全，并在短信确认后执行不可恢复注销。

## 决定

- `[PRD]` 新增注销条件检查、注销验证码和确认注销三个接口，验证码只发送到绑定手机号。
- `[DESIGN]` 固定返回 `orders/wallet/services/security` 四项条件，全部通过后才允许注销。
- `[DESIGN]` 注销后账号主体保留为 `LOGOFF`，撤销全部令牌并清理登录绑定、个人资料、动态、评论、点赞、收藏、关注和可清理的个人媒体。
- `[DESIGN]` 交易、支付、退款、提现、聊天、客服、评价和安全审计保留业务关联；实名、服务者申请中的敏感字段匿名化。
- `[DESIGN]` `account_deletion_records` 保存条件快照、清理数量、验证码请求标识和完成时间；单用户唯一约束和事务锁保证不重复清理。
- `[CONFIRM]` 生产短信服务商和会员、优惠券等尚未上线权益的清理规则。

## 影响

- 新增账号注销 API、验证码用途、审计表和迁移。
- 不删除订单、支付、退款、聊天和安全审计事实数据，不绕过资金一致性约束。
