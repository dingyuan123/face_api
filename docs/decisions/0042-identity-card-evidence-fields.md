# ADR-0042：实名认证身份证正反面资料

- 状态：已接受
- 日期：2026-11-13
- 决策人：项目负责人

## 背景

- 服务者入驻申请需要申请人提交姓名、身份证号和身份证正反面照片。
- 项目已经存在 `identity` 实名/人脸状态模块，但没有保存证件资料或照片引用。

## 决策

- `[DESIGN]` 服务者申请新增身份证正面和反面媒体引用，上传时使用专用媒体用途。
- `[DESIGN]` 实名认证记录同步保存姓名密文、身份证号密文、身份证 HMAC 和正反面媒体引用。
- `[DESIGN]` 姓名和身份证号继续不返回接口；照片通过 `MediaAssetSummary` 仅供本人回显和管理员审核。
- `[DESIGN]` 普通用户和服务者实名资料统一进入人工审核，审核通过后状态为 `PASSED`；本期不接人脸认证，不执行人脸 Mock。
- `[DESIGN]` 服务者申请新增紧急联系人姓名和手机号密文字段，响应仅提供姓名和脱敏手机号。

## 备选方案

- 只在申请表保存照片、不进入身份认证记录：后续真实实名适配无法复用完整证据链。
- 将照片 Base64 存数据库：文件大、备份和访问控制差，继续使用媒体资产存储。
- 立即接入真实 OCR/公安核验：缺少厂商、密钥、合规和留存规则，当前只建立数据边界。

## 影响

- 媒体上传新增 `IDENTITY_CARD_FRONT/IDENTITY_CARD_BACK` 用途。
- 服务者申请创建、重提、管理审核和 OpenAPI 增加正反面照片字段。
- 服务者申请增加紧急联系人姓名和手机号的加密存储与脱敏展示。
- 数据库迁移新增申请和身份认证证件字段，不回填历史明文。

## 风险与缓解

- 证件照片高度敏感：只允许本人上传，业务接口按本人/管理员隔离，日志不记录媒体内容。
- 历史申请可能缺少照片：字段允许空值，新申请强制提交。
- 真实 OCR/公安核验尚未接入：状态只表示人工审核结果，不冒充自动核验通过。

## 验证

- 自动化测试覆盖字段校验、所有权、媒体用途、密文不泄露和 Mock 状态。
- 运行迁移检查、完整 pytest、Ruff 和 OpenAPI。
