# ADR-0046：内容举报和敏感词管理

- 状态：已接受
- 日期：2026-11-16
- 决策人：项目负责人

## 背景

- 管理后台需要处理用户对动态、资讯、用户和服务的举报。
- 内容风控还缺少敏感词配置、命中处理和管理审计。

## 决策

- `[DESIGN]` 新增 `ContentReport`，支持用户提交举报和管理员处理。
- `[DESIGN]` 新增 `SensitiveWord` 和 `SensitiveWordMatchLog`，敏感词支持启用/停用、拦截/转人工审核。
- `[DESIGN]` 举报处理和敏感词写操作使用 `expected_version`、管理员权限点和统一 `AdminOperationLog`。
- `[DESIGN]` 当前先实现举报 CRUD/处理和敏感词基础配置，批量导入导出、AI 审核和跨内容匹配引擎后续接入。

## 影响

- 用户可通过 `/api/v1/reports/` 提交举报。
- 管理员通过 `/admin/v1/reports/` 和 `/admin/v1/sensitive-words/` 进行处理和配置。

## 风险与缓解

- 举报重复：按举报人、目标类型和目标标识唯一约束。
- 敏感词误伤：保留人工处理动作和停用开关。
- 证据地址风险：仅保存 URL 列表，后续需增加安全抓取和病毒扫描。

## 验证

- 自动化测试覆盖举报提交/处理、敏感词创建/修改/停用、权限和版本冲突。
