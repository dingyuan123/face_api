# ADR 0021: 钱包余额预约、社交互动和评价

- 状态：Accepted
- 日期：2026-10-31
- 范围：钱包余额、预约订单、关注收藏点赞评论和订单评价

## 决策

- `[PRD]` 用户可以预约服务、使用余额支付、关注/收藏/互动并评价完成订单。
- `[DESIGN]` 当前支付方式为 `BALANCE`，由钱包余额同步扣款并写不可变 `CREDIT/DEBIT` 流水。
- `[DESIGN]` 用户不能自主充值；管理员通过测试充值接口写入开发余额，生产禁止 `DEV_MOCK` 和 `MOCK_BALANCE`。
- `[DESIGN]` 订单保存服务、服务者、时段和价格快照；预约时段创建、锁定、取消释放均受版本和唯一约束保护。
- `[DESIGN]` 订单支付成功进入 `PENDING_ACCEPT`，后续接单、开始、完成、用户确认形成完整状态日志。
- `[DESIGN]` 当前取消/拒绝订单使用全额余额退款，接单后取消惩罚需求保留但不执行。
- `[DESIGN]` 关注、收藏、点赞、评论使用唯一关系和幂等操作；评论第一阶段为一级评论。
- `[DESIGN]` 评价只允许订单完成后 7 天内发表，一个订单一次评价；7 天未评价自动好评留待后续 Celery 定时任务。
- `[CONFIRM]` 真实微信/支付宝、充值、退款/违约金、排期规则、自动好评和评价修改/匿名规则。

## 影响

- 前端可以完成余额支付的预约闭环和基础社交互动。
- 支付适配层可后续增加微信/支付宝，而钱包流水和订单快照保持兼容。
