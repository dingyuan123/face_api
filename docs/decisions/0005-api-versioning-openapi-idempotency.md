# ADR-0005：统一版本化 API、OpenAPI 和幂等协议

- 状态：提议（待技术负责人确认）
- 日期：2026-10-27
- 决策人：待技术负责人确认 `[CONFIRM]`

## 背景

iOS、Android、微信小程序共用 API，且支付、退款、订单、奖励和提现必须重复请求安全。

## 决策

- `[DESIGN]` 客户端 API 固定 `/api/v1`，管理 API 固定 `/admin/v1`，版本变化通过路径升级。
- `[DESIGN]` 统一响应、错误码、trace_id、游标分页、RFC 3339 UTC 时间和 `amount_minor` 金额。
- `[DESIGN]` 写接口支持 `Idempotency-Key`；服务端按用户、路由、请求体哈希和结果记录重复请求。
- `[DESIGN]` 支付/退款回调按渠道事件 ID、渠道交易号和业务单号幂等。
- `[DESIGN]` 使用 drf-spectacular 生成 OpenAPI，CI 校验接口、示例和错误码。

## 备选方案

- 无版本路径：短期简单，但破坏三端兼容和灰度。
- 仅依赖 HTTP 重试：无法防止客户端重复点击、渠道重复回调和乱序事件。

## 影响

- 客户端可稳定处理错误和重试；服务端需维护幂等存储和 schema 测试。

## 风险与缓解

- 风险：幂等键被跨用户重用。缓解：按用户/租户/路由隔离。
- 风险：API 文档漂移。缓解：CI schema diff 和契约测试。

## 验证

- 重复 POST、不同用户同键、请求体变化、支付/退款回调乱序和 OpenAPI diff 测试。
