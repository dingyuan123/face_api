# ADR 0023: 默认小时网格和连续时段预约

- 状态：Accepted
- 日期：2026-11-02
- 范围：默认排期网格、服务时长、连续时段锁定和订单关联

## 背景

服务者需要每天看到可设置的小时单元，并主动决定可约或休息。不同服务时长可以不同，但均为 60 分钟倍数。当前一个订单只能关联一个预约时段，无法安全锁定两小时及以上服务。

## 决策

- `[DESIGN]` 每天默认生成 `00:00–24:00` 的 60 分钟单元，初始状态为 `CLOSED`，不自动开放给用户。
- `[DESIGN]` 当前排期统一使用服务者通用时段，不绑定具体服务；服务者通过单时段或批量操作把单元切换为 `OPEN`，周规则代表服务者主动开放的时间范围。
- `[DESIGN]` 服务时长必须是 60 分钟倍数；当前不设置最大总时长，保留 `SCHEDULE_MAX_BOOKING_MINUTES` 配置，0 表示不限制。
- `[DESIGN]` 创建订单的 `slot_id` 表示预约起始单元，后端按服务时长检查并锁定连续 N 个单元。
- `[DESIGN]` `order_schedule_slots` 保存订单与全部连续单元的有序关联；任一单元不可用时订单创建整体失败。
- `[DESIGN]` 支付、完成、取消和退款维护所有关联单元；取消释放全部单元并保留 `last_booking_status=CANCELLED`。

## 影响

- 排期日历不再返回空的未配置日期，而是返回 24 个默认小时单元。
- 多小时服务不会只锁定首小时，避免并发超卖。
- 后续可以增加最大预约时长，不需要改变订单与时段关联模型。
