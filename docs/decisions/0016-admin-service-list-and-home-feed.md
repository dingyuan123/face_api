# ADR 0016: 管理员服务列表与首页服务者卡片

- 状态：Accepted
- 日期：2026-10-30
- 范围：管理员服务管理列表、首页服务者卡片和完整动态流边界

## 背景

管理员需要查看全平台服务，首页需要展示服务者卡片。用户确认卡片必须包含性别，没有动态时使用申请生活照、服务者照片墙和相关服务照片中的最近 3 到 5 张。

## 决策

- `[PRD]` 管理员服务列表支持状态、服务者、类目和关键词筛选；首页卡片展示服务者、照片、性别、服务和认证状态。
- `[DESIGN]` `GET /api/v1/admin/provider-services/` 返回服务、服务者公开标识、脱敏手机号、价格、媒体、状态、版本和全平台状态汇总。
- `[DESIGN]` `GET /api/v1/home/feed/` 公开返回服务者卡片；未登录最多 10 张，登录最多 20 张，使用游标分页。
- `[DESIGN]` 卡片照片按创建时间倒序聚合服务者照片墙、申请生活照、头像和已上架服务封面/图集，去重后最多返回 5 张。
- `[DESIGN]` 卡片返回性别、年龄、城市代码、认证状态、服务摘要和临时 `display_url`；没有可靠距离/评分/实时在线状态时返回 `null/UNKNOWN`。
- `[DESIGN]` 当前首页只展示至少一条 `ONLINE` 服务的服务者，服务项目最多返回 3 条。
- `[DESIGN]` 完整动态、视频、距离、评分、热度和推荐排序需要 `moments/moment_media`、位置/GeoProvider、评价和曝光数据，后续在 `discovery` 中演进。
- `[CONFIRM]` 完整动态卡片流、视频审核、距离精度、在线状态判定、评分热度和推荐权重。

## 影响

- 前端可以先联调管理员服务管理和首页服务者卡片，不依赖尚未实现的动态模块。
- 照片来源是聚合读模型，后续动态上线后可逐步替换为动态媒体。

## 验证

- `tests/test_home_feed.py` 覆盖性别、最近照片、筛选、游客限制和管理员服务列表。
- pytest、Ruff、Django check、迁移检查和 OpenAPI 校验作为提交门槛。
