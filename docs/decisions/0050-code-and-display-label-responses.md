# 0050. 状态、标签和审计的代码与中文展示

- 日期：2026-11-21
- 状态：已实施

## 背景

App 和管理后台需要直接展示兴趣标签、服务标签、状态和审计动作的中文含义，同时继续使用稳定代码进行筛选、提交和数据关联。

## 决定

- `[PRD]` 第一批统一补齐账号、服务者申请、服务状态、资料/服务标签和管理审计的中文展示。
- `[DESIGN]` 请求参数继续只接收稳定代码；响应保留原代码，并增加 `*_text` 或完整标签对象，不破坏现有客户端。
- `[DESIGN]` 固定状态从 Django `TextChoices` 读取标签；审计动作和对象类型使用管理端集中映射。
- `[DESIGN]` 标签对象包含 `code/name/category/sort_order`；缺失配置使用 `is_missing=true` 和可识别的空名称，不伪造中文名称。
- `[DESIGN]` 审计未知动作回退为“未知操作”，同时继续返回原始代码，保证历史记录可排查。
- `[CONFIRM]` 后续是否需要英文展示、名称版本快照和全量枚举元数据接口。

## 影响

- 更新账号、服务者资料、公开资料、服务、订单服务摘要和管理审计响应。
- 不改变数据库状态、提交协议或业务状态机。
