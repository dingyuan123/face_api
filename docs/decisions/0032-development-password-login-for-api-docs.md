# ADR-0032：Swagger 联调用开发账号密码登录

- 状态：已接受
- 日期：2026-11-06
- 决策人：项目负责人（本次确认直接实施）

## 背景

开发和前端联调使用 Swagger 时，每次通过手机号发送验证码再登录较繁琐。需要一个方便获取 Bearer Token 的测试入口，但不能把未经确认的密码登录写成正式产品能力。

## 决策

- `[DESIGN]` 新增 `POST /api/v1/dev/auth/password-login/`，只验证已经设置密码哈希的已有手机号账号。
- `[DESIGN]` 成功后复用正式登录的 `TokenPairResponseSerializer`，签发独立会话的访问/刷新令牌，后续刷新、退出和权限校验规则不变。
- `[DESIGN]` 接口支持 `Idempotency-Key`，同键同请求复用令牌，同键不同请求返回冲突。
- `[DESIGN]` `ENABLE_DEV_PASSWORD_LOGIN` 只允许在非生产环境开启；`DJANGO_ENV=production` 强制禁用并隐藏为 404。
- `[DESIGN]` Swagger UI 开启 `persistAuthorization`，调用登录接口后把 `access_token` 填入 Authorize 的 Bearer Token。
- `[CONFIRM]` 正式账号密码登录、密码设置/找回、限流、异常登录和双因素认证仍需产品和安全负责人确认。

## 备选方案

- 自动把登录结果写入 Swagger Authorize：需要替换或深度定制 Swagger UI，增加维护和安全复杂度。
- 使用 HTTP Basic 作为全局认证：无法复用现有 Bearer 会话、刷新和退出生命周期。
- 在代码写死测试账号密码：违反密钥/凭据不提交 Git 的要求。

## 影响

- Swagger 联调可直接用已有密码账号获取 Token，不再每次发送验证码。
- 不新增用户密码数据结构；只复用当前用户密码哈希。
- 正式 App 登录仍以手机号验证码为准，不能依赖该开发接口。

## 风险与缓解

- 风险：开发接口误用于生产。缓解：生产环境配置层强制关闭，并增加开关和生产禁用测试。
- 风险：Swagger 持久保存 Token 导致共用浏览器泄露。缓解：文档警示、令牌可退出撤销，不记录 Token 明文。
- 风险：密码暴力尝试。缓解：当前只限开发环境；正式密码登录前必须增加限流、异常检测和审计。

## 验证

- 正确密码登录并使用返回的 Bearer Token 访问用户接口。
- 错误密码、未知账号、未设置密码、非正常账号和关闭开关均拒绝。
- 验证幂等令牌复用、冲突、刷新轮换、退出撤销和日志脱敏。
- 验证 OpenAPI 请求参数、只写密码字段和生产禁用说明。
