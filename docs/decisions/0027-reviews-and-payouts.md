# 0027. 评价管理、收益账户和提现

- 日期：2026-11-05
- 状态：已确认测试阶段方案
- 范围：评价页面、服务者评价管理、订单收入、收款方式、收益账户和提现

## 背景

前端需要“我的评价”、服务者评价管理和服务者收入提现能力。普通用户后续通过分享获得推广收益，因此普通用户也需要提现账户。当前尚未接入真实微信、支付宝、银行卡和打款渠道。

## 决策

1. 普通用户和服务者共用 `PayoutMethod` 绑定数据，支持 `BANK_CARD`、`ALIPAY`、`WECHAT_PAY`；后续 OAuth 授权通过适配器扩展，不改变现有绑定接口。
2. 测试阶段使用模拟账户验证、模拟打款和管理员人工审核。生产配置禁止 Mock。
3. 收益账户区分 `PROVIDER_INCOME` 和 `REFERRAL_REWARD`，账户金额、冻结、收入和提现均使用不可变流水追溯。
4. 订单确认完成后，在订单事务内幂等生成服务者收入记录。当前佣金和结算延迟是测试配置，不代表生产财务规则。
5. 提现申请冻结余额，管理员审核通过后模拟打款；拒绝、撤销和失败释放冻结金额，失败单保留并支持重试。
6. 收款方式账号加密保存，只返回脱敏值；支持默认收款方式和逻辑停用。
7. 我的评价返回待评价订单和历史评价；评价响应返回服务摘要、评价用户摘要、服务者摘要和最新回复。匿名评价不泄露评价用户身份。
8. 服务者评价管理支持评分、回复状态和日期筛选，返回评分分布、平均分、回复数和回复率；同一评价只保留一条服务者回复。

## 影响

- 新增 `backend/payouts` 模块、评价管理接口、收益账户、提现单和状态审计。
- 订单完成流程增加收入入账，重复确认必须保持幂等。
- 资金相关接口必须继续使用幂等键、版本并发控制和数据库约束。
- 真实支付、OAuth 绑定、银行卡鉴权、佣金结算和推广奖励生成仍是后续任务。

## 未决事项

- 正式佣金比例、结算周期、手续费、税费、最低提现金额和打款失败处理。
- 微信、支付宝 OAuth 和真实打款渠道选型。
- 评价匿名展示、内容审核、追评、申诉和评分清洗规则。
