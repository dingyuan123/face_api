# ADR-0009：手机号验证码登录与不透明令牌

- 状态：提议（开发/测试方案已实施，生产短信和隐私规则待确认）
- 日期：2026-10-28
- 决策人：待确认

## 背景

- `[PRD]` 手机号注册登录必须支持，首次登录/注册后选择身份，手机号不能明文泄露。
- 当前没有阿里云或其他短信服务商凭据，开发联调需要能看到随机 6 位验证码。

## 决策

- `[DESIGN]` 新建 `accounts` 模块，分离 HTTP、序列化、应用服务、认证器和持久化模型。
- `[DESIGN]` 验证码保存慢哈希、过期、尝试和消费状态；开发/测试 mock 返回 `debug_code`，生产强制关闭。
- `[DESIGN]` 登录在事务中消费验证码，并按 `auth_type + auth_identifier` 创建或读取用户；当前采用自动注册。
- `[DESIGN]` 使用服务端生成的不透明访问/刷新令牌，只持久化哈希；刷新令牌轮换并撤销旧令牌。
- `[DESIGN]` 发送限流由数据库守卫行控制；验证码发送和登录通过幂等键支持重复请求。

## 备选方案

- JWT 自包含令牌：无需集中撤销，但本阶段无法充分满足封禁和异常撤销要求。
- Redis 保存验证码和限流：实现快，但不能作为验证码消费和重复登录的最终事实。
- 明文保存开发验证码：便于调试，但扩大敏感数据风险，不采用。

## 影响

- 需要 `AUTH_TOKEN_SIGNING_KEY`、`PHONE_HASH_KEY` 和开发用 `SMS_MOCK_SIGNING_KEY`。
- 数据库新增用户、认证凭据、验证码、登录幂等和令牌表迁移。
- OpenAPI 新增短信验证码、登录、刷新和当前会话接口。

## 风险与缓解

- `[CONFIRM]` 自动注册与 PRD 的注册/登录接口清单不完全一致；可新增独立注册接口而不改变用户模型。
- `[CONFIRM]` 生产短信服务商和验证码风控阈值未确定；生产未接适配器时明确失败，不静默返回验证码。
- `[CONFIRM]` 手机号哈希无法直接支持号码找回/客服展示，需要后续确认可逆加密或受控密文方案。
- `[CONFIRM]` 令牌有效期、设备并发和注销撤销范围未确认，当前数值仅为可配置开发默认值。

## 验证

- `tests/test_auth.py` 覆盖发送、登录、自动注册、幂等、验证码生命周期、令牌认证和刷新轮换。
- 迁移检查、OpenAPI 校验、pytest 和 Ruff 必须通过；PostgreSQL 并发压测留待集成环境验证。
