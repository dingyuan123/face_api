# ADR-0003：使用 PostgreSQL 账本保证资金一致性

- 状态：提议（待产品、财务和技术负责人确认）
- 日期：2026-10-27
- 决策人：待产品、财务和技术负责人确认 `[CONFIRM]`

## 背景

PRD 要求支付、退款、结算、奖励、提现幂等，余额可追溯，金额禁用 Float，历史规则快照不可覆盖。

## 决策

- `[DESIGN]` PostgreSQL 为主事实；金额用 `BIGINT` 分，比例用 `rate_bp` 整数。
- `[DESIGN]` 余额是汇总值，每次变化在同一事务写不可变 `wallet_transactions`。
- `[DESIGN]` 订单保存服务、价格、佣金、退款和奖励政策快照；政策版本只追加。
- `[DESIGN]` 唯一约束、状态条件、乐观锁和行锁共同防止重复/超卖/重复入账。

## 备选方案

- Redis 余额：延迟低但不是可靠账本，不能满足审计和恢复。
- Decimal/浮点混合：Decimal 可行但浮点禁止；统一整数分减少舍入和跨语言差异。

## 影响

- 所有资金命令需事务、流水、幂等键、状态日志和对账。
- 迁移、备份、恢复和人工调账成本提高，但资金风险降低。

## 风险与缓解

- 风险：业务服务绕过账本。缓解：钱包公开服务、数据库约束、审计和测试。
- 风险：分账/二清法律风险。缓解：持牌支付机构与合规方案必须确认。

## 验证

- 金额守恒、流水重放、重复回调、并发入账、退款冲减、提现失败恢复和每日对账测试。
