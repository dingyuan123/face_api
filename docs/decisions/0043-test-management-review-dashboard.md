# ADR-0043：开发测试管理审核后台

- 状态：已接受
- 日期：2026-11-13
- 决策人：项目负责人

## 背景

- 当前 Django Admin 偏向只读查看，实名认证和服务者入驻审核操作分散在接口中，开发测试不方便。
- 管理员需要集中查看待审核量、证件照片、服务者资料，并执行有版本控制的人工审核。

## 决策

- `[DESIGN]` 新增 `/management/` 服务端管理后台，首期只覆盖总览、普通用户实名认证审核和服务者入驻审核。
- `[DESIGN]` 后台使用现有 `is_staff` 管理员认证，不新增独立管理员密码体系。
- `[DESIGN]` 所有审核操作调用 `identity.services`、`providers.services` 等业务服务，不直接修改数据库。
- `[DESIGN]` 页面展示证件和申请照片的安全媒体地址，不显示身份证号、密文或完整手机号。
- `[DESIGN]` 审核动作提交 `expected_version` 和原因，复用现有状态机、审计事件和人工审核约束。

## 备选方案

- 直接放开 Django Admin 编辑：容易绕过业务状态机和版本冲突，不适合资金、身份和审核数据。
- 只做管理 API：测试人员仍需额外前端工具，无法快速浏览和审核照片。
- 一次性建设完整运营后台：范围过大，首期先解决实名和服务者审核瓶颈。

## 影响

- 新增 `backend.adminops` 页面模块和 `/management/` 路由。
- 首期不包含订单、退款、推广奖励和内容管理，后续按现有管理 API 扩展页面。

## 风险与缓解

- 管理员误操作：审核动作要求版本号和原因，复用业务服务的状态校验。
- 证件照片泄露：只允许 `is_staff` 登录后查看，图片继续使用短期签名媒体地址。
- 双人复核和生产 RBAC 尚未接入：当前后台仅用于开发测试，生产启用前必须增加独立管理员权限和审计。

## 验证

- 自动化测试覆盖管理员访问、实名审核、服务者审核和未登录跳转。
- 运行 Django 检查、完整 pytest、Ruff 和 OpenAPI。
