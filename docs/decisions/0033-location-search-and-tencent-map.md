# ADR 0033：地点搜索和腾讯地图适配

- 状态：已确认
- 日期：2026-11-07
- 决策人：产品、前端和后端共同确认

## 背景

下单前需要在地图上选择符合平台要求的公共场所。PRD 要求地点为公共场所，并允许地图服务完成地址搜索和距离展示。

## 决策

- `[PRD]` 地点必须是公共场所，酒店和私人居住场所不进入下单地点。
- `[DESIGN]` 后端提供登录用户快捷关键词和地点搜索接口，第三方地图能力通过 `integrations/geo` 契约接入。
- `[DESIGN]` 当前接入腾讯地图周边搜索；业务模块不直接依赖腾讯响应结构，密钥只在运行环境配置。
- `[DESIGN]` 搜索采用请求关键词拒绝、POI 分类/名称/地址过滤两层规则；医院、学校、政府机构当前允许。
- `[DESIGN]` 前端传 `coordinate_system=GCJ02/WGS84`，服务端统一坐标后计算直线距离并按请求坐标系返回。
- `[DESIGN]` 快捷关键词使用数据库配置和乐观锁版本管理，创建接口支持幂等键，停用不删除历史配置。
- `[DESIGN]` 当前不保存用户精确位置搜索记录；粗粒度缓存只用于短期降低第三方调用。
- `[DESIGN]` 后续订单保存完整地址、经纬度和 POI 快照，并由后端校验搜索结果或地点选择凭证。

## 影响

- 前端可以完成地图选点、快捷搜索和距离展示。
- 地点分类策略可以通过配置扩展，不需要修改搜索主流程。
- 腾讯配额、分类字典和地址字段授权仍是外部依赖。

## 验证

- 自动化测试覆盖权限、过滤、距离、坐标系、幂等、版本冲突和第三方失败。
- OpenAPI 覆盖搜索查询、结果、快捷关键词和管理员配置。
- 真实腾讯 Key、网络、配额、分类返回和生产位置隐私需要人工或沙箱验证。
