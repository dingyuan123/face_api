# 安全与数据保护规范

## 1. 基本原则

- `[PRD]` 全站 HTTPS/TLS；防止 SQL 注入、XSS、CSRF、越权、重放、刷接口和文件上传漏洞。
- `[PRD]` 未满 18 岁禁止注册；服务严格限于公共场所合法活动，禁止性服务、性暗示、私密场所和场外交易。
- `[DESIGN]` 默认拒绝。任何接口、字段、导出、后台命令和第三方回调都必须有明确的授权、校验、审计和数据最小化。
- `[DESIGN]` 安全校验不能为了调试、演示或测试关闭；测试使用专用环境和假适配器。

## 2. 身份认证

- `[DESIGN]` 密码使用 Argon2id（或 bcrypt 的同等强参数），服务端强制强度和防枚举响应。
- `[DESIGN]` 手机验证码限频、短时有效、一次性使用；登录/注册/重置均有设备和 IP 风险检查。
- `[DESIGN]` 第三方登录保存平台 subject/openid/unionid 映射，不能接受客户端自称的 user_id。
- `[DESIGN]` 访问令牌短时有效；刷新令牌旋转、设备绑定、过期和撤销可审计。退出撤销当前设备会话，封禁/注销立即撤销对应会话。
- `[DESIGN]` 退出与令牌刷新在同一用户锁下执行，避免并发刷新在退出后补发有效令牌。
- `[DESIGN]` 退出不记录访问/刷新令牌明文；请求追踪只记录用户和请求追踪信息，不记录令牌内容。
- `[CONFIRM]` 退出全部设备、设备管理、异常远端撤销和相关审计的保留期限。
- `[DESIGN]` 管理员独立账号体系，高风险角色启用 MFA，禁止用普通用户令牌访问后台。

### 2.1 手机号验证码登录

- `[PRD]` 手机号是个人信息，不能明文泄露；未满 18 岁禁止注册。
- `[DESIGN]` 手机号使用独立密钥生成可检索 HMAC 哈希，保存必要脱敏尾号；日志、错误详情和 OpenAPI 示例不得出现完整手机号。
- `[DESIGN]` 验证码只在开发/测试 mock 模式通过 `debug_code` 返回；生产配置强制 `SMS_MOCK_ENABLED=false`，未接短信适配器时明确返回服务不可用。
- `[DESIGN]` 验证码使用慢哈希保存并一次性消费；发送、登录和令牌轮换使用数据库事务、唯一约束和请求幂等记录处理重复与并发。
- `[DESIGN]` 访问/刷新令牌由服务端生成，数据库只保存 SHA-256 哈希；令牌、验证码和手机号不进入应用日志。
- `[CONFIRM]` 生产短信服务商、验证码重发/尝试阈值、手机号保存期限、令牌有效期和设备并发上限。

## 3. 授权与资源访问

- `[DESIGN]` 每个写操作校验动作权限、资源归属、资源状态和版本；“已登录”不等于可操作任何资源。
- `[DESIGN]` 用户只能读取/修改自己的资料、订单、会话、钱包和奖励；服务者只能操作自己的服务、排期、订单和收入。
- `[DESIGN]` 客服按工单/案件访问脱敏订单和聊天；管理员按 RBAC 细分用户、内容、订单、财务、风控、推广权限。
- `[DESIGN]` 后台列表查询和导出同样受权限、筛选范围、数量和审计约束，不因“内部接口”放宽。
- `[CONFIRM]` 客服、财务、风控、管理员的角色矩阵、查看敏感字段级别、审批人和时效。

## 4. 输入、输出和文件

- `[DESIGN]` 使用 DRF serializer/validator、白名单枚举、长度/数量/坐标/金额边界和结构化参数；禁止拼接 SQL。
- `[DESIGN]` 输出统一脱敏：手机号、证件、银行卡、令牌、人脸、精确位置不回传；异常信息不泄露栈、SQL、密钥或第三方响应。
- `[DESIGN]` 文件上传使用受控对象存储凭证，校验大小、MIME、真实文件类型、哈希和恶意内容；服务端不代理任意 URL。
- `[DESIGN]` 前端提交的价格、佣金、奖励比例、状态、用户/订单 ID 一律不信任，重新从数据库快照和当前权限计算。

## 5. 支付、退款和资金

- `[PRD]` 支付接口 HTTPS，资金由持牌支付机构处理；支付、退款、结算、奖励、提现必须幂等。
- `[DESIGN]` 支付/退款回调必须验签、核对商户/应用/订单号/金额/币种/时间戳、防重放；原始回调加密或受限留存。
- `[DESIGN]` 资金变更只在数据库事务和不可变流水中发生；账户余额不能由客户端或 Redis 直接改。
- `[DESIGN]` 提现需账户实名/风险校验、余额冻结、管理员审核、渠道打款结果回调和反向流水；高风险提现可人工复核。
- `[DESIGN]` 对账差异进入告警和人工队列，禁止静默修正。
- `[CONFIRM]` 支付商户主体、二清/分账合规方案、退款/违约金、提现税费和人工调账审批。

## 6. 敏感数据保护

- `[PRD]` 手机号、身份证、人脸、银行卡、聊天记录加密；位置模糊化；日志禁止明文密码、证件、人脸、完整银行卡和支付凭据。
- `[DESIGN]` 采用信封加密，密钥由 KMS/密钥服务管理并定期轮换；数据库只保存密文、受控引用和必要哈希。
- `[DESIGN]` 身份证、人脸等只在认证服务内解密；业务接口只返回状态、脱敏摘要和时间。
- `[DESIGN]` 订单联系手机号使用 `IDENTITY_ENCRYPTION_KEY` 加密保存；只有订单本人或服务者在允许联系的订单状态下，才能读取对方拨号号码。
- `[DESIGN]` 订单列表只返回脱敏手机号，完整拨号号码不写日志、不写 trace、不进入缓存或审计明细。
- `[DESIGN]` 日志、trace、备份、导出、监控告警同样脱敏；开发/测试禁止使用生产数据。
- `[DESIGN]` 数据保留、删除、匿名化、司法调取和备份清除必须按隐私政策执行，不能用软删除替代合规处置。
- `[CONFIRM]` 个人信息保存期限、跨境/云厂商、注销后保留、位置精度和报警数据访问流程。

### 6.1 服务者身份资料

- `[DESIGN]` 真实姓名和身份证号通过 `IDENTITY_ENCRYPTION_KEY` 信封加密保存；身份证额外保存带服务端密钥的 HMAC 用于受控查重，避免低熵证件号被普通字典直接碰撞。
- `[DESIGN]` 身份 Mock 请求号使用随机不含个人信息的标识；Mock 不把姓名、身份证尾号或完整手机号写入请求号和日志。
- `[DESIGN]` `MOCK_PASSED` 仅允许开发/测试配置；生产配置启动时强制要求真实密钥并禁止 `IDENTITY_MOCK_ENABLED=true`。
- `[DESIGN]` 服务者申请创建、用户查询和管理员查询使用同一套脱敏响应，不能因为管理端查询而默认返回证件明文。
- `[DESIGN]` 最小管理员审核记录申请人、状态前后值、审核人、原因、版本和 trace_id；正式后台接入统一 `admin_operation_logs` 后应关联该事件。
- `[CONFIRM]` 真实实名/人脸凭据、证件图片、活体数据的加密、访问、留存、删除、导出和司法调取流程。

### 6.2 当前本地媒体存储

- `[DESIGN]` 媒体文件当前写入 `MEDIA_ROOT`，数据库只保存生成的存储键和内容哈希；存储目录不提交 Git。
- `[DESIGN]` 上传文件的客户端 MIME/文件名不作为事实，服务端解码真实图片后重新编码，只保留单帧 JPEG/PNG/WebP。
- `[DESIGN]` 重新编码会移除 EXIF/GPS 等元数据；文件大小、尺寸、像素量和格式均有限制。
- `[DESIGN]` 媒体内容接口要求 Bearer 认证并校验所有者或 `is_staff`，响应禁止公共缓存。
- `[DESIGN]` 后续 OSS/COS 只通过存储适配器替换，业务模块不依赖厂商 SDK；生产对象存储必须使用最小权限、私有桶和短期签名地址。
- `[DESIGN]` `display_url` 是短期 HMAC 能力地址，签名覆盖媒体 ID、过期时间和密钥版本；签名错误返回 403，过期返回 410。
- `[DESIGN]` 当前展示地址不绑定登录用户，持有地址者在有效期内可访问；默认 10 分钟，过期后必须重新签发。
- `[DESIGN]` 当前申请照片只在申请人或管理员授权后签发展示地址；未来公开头像/动态必须经过业务审核和发布状态，聊天媒体还需要订单/会话关系校验。
- `[DESIGN]` 签名密钥独立于身份加密密钥，使用 `MEDIA_URL_SIGNING_KEY` 和 `key_version` 支持轮换；签名和查询参数不写入应用日志。
- `[CONFIRM]` 公共图片/视频的 CDN、缓存、保留删除、视频签名和聊天媒体访问策略。
- `[CONFIRM]` 图片/视频审核、病毒扫描、保留期限、删除流程、CDN 公开范围、水印和原图下载权限。

### 6.3 用户个人资料

- `[DESIGN]` 昵称在数据库使用忽略大小写唯一约束，防止大小写变体重复占用。
- `[DESIGN]` 年龄、性别、城市和标签由服务端校验，不信任前端传入的等级、认证状态或用户 ID。
- `[DESIGN]` 安心用户等级字段只读预留，资料修改接口不接受等级参数。
- `[DESIGN]` 个人资料响应不返回手机号哈希、认证密文、令牌或其他账号敏感字段。
- `[CONFIRM]` 昵称/签名内容审核、公开资料展示范围、头像审核和等级维护权限。

### 6.4 服务者资料和服务

- `[DESIGN]` 服务者资料昵称忽略大小写唯一；服务者只能修改自己的资料、服务、图片和状态，可复用本人申请阶段媒体。
- `[DESIGN]` 服务金额使用整数最小货币单位，任何折扣、退款、佣金和结算不得使用 Float；订单创建时必须保存价格快照。
- `[DESIGN]` 服务价格、类目、时长、状态、已售数量和审核结果由服务端校验；客户端不能提交已售数量或审核状态。
- `[DESIGN]` 服务图片必须引用本人正确媒体用途，状态操作使用版本号并记录服务事件。
- `[DESIGN]` 逻辑删除草稿/拒绝服务并保留事件，避免破坏后续订单和审计追溯。
- `[CONFIRM]` 服务内容审核、图片审核、折扣/优惠券价格快照、订单已售数量事件和删除保留策略。

### 6.5 服务者动态

- `[DESIGN]` 动态只能由已开通服务者发布，媒体必须属于发布者并使用 `MOMENT_IMAGE` 用途。
- `[DESIGN]` 动态公开查询只返回 `PUBLISHED + PUBLIC`，不泄露草稿、审核中或私密动态。
- `[DESIGN]` 当前发布直接通过只是开发/联调策略，管理员审核接口和状态保留；正式上线前必须确认先审后发还是先发后审。
- `[DESIGN]` 动态删除采用逻辑删除并保留事件，挂载服务必须是本人 `ONLINE` 服务。
- `[CONFIRM]` 动态内容/图片审核、敏感词、举报、推荐权重、视频留存和删除策略。

### 6.6 钱包、预约订单和评价

- `[DESIGN]` 钱包余额、支付、退款和测试充值均使用整数最小货币单位，余额变化必须写不可变流水。
- `[DESIGN]` 用户不能自主充值；测试充值只允许管理员在测试配置下调用，生产禁止测试充值和 Mock 支付。
- `[DESIGN]` 订单保存服务/价格/时段快照，任何服务修改不能改变历史订单金额。
- `[DESIGN]` 钱包支付、退款、订单创建和状态变化均使用幂等键、版本或唯一约束；不能由前端提交余额、已付金额、评分或订单状态。
- `[DESIGN]` 当前余额退款只做全额原路退回；接单后取消惩罚需求保留，但当前不执行，不能据此伪造扣费。
- `[DESIGN]` 评价只允许已完成订单在 7 天窗口内发表，评分聚合由服务端计算。
- `[CONFIRM]` 真实支付渠道、退款/违约金、自动好评、隐私展示和评价内容审核。

## 7. 内容、IM 与线下安全

- `[PRD]` 动态/聊天 AI 预审 + 人工复核；敏感词、反垃圾、反欺诈、举报、黑名单和申诉。
- `[DESIGN]` 内容和消息发布前/后按风险策略处理；拒绝、删除、冻结、封禁都保留理由、证据、版本和审计。
- `[DESIGN]` 会话只在有效订单关系解锁；拉黑、退款、取消和订单完成后的访问按配置执行。
- `[DESIGN]` 报警和行程分享只收集必要位置/联系人/订单证据，按权限展示，记录访问和导出。
- `[CONFIRM]` 动态先审后发、聊天审核范围、报警响应流程、紧急联系人通知和数据留存。

## 8. 后台和审计

- `[DESIGN]` 管理员 RBAC、最小权限、会话超时、敏感操作二次确认、原因和可选双人复核。
- `[DESIGN]` `admin_operation_logs` 记录管理员、IP、模块、动作、业务 ID、前后值、原因、trace_id 和时间；日志不可修改。
- `[DESIGN]` 封禁/解封、审核、仲裁、退款批准、奖励冻结/调整、提现审核、配置变更、数据导出必须审计。
- `[DESIGN]` 高风险命令支持撤销/补偿，但不删除原记录。
- `[DESIGN]` Django Admin 当前仅用于开发查看，登录使用手机号转换后的账号标识，业务模型默认只读，避免绕过业务服务直接修改状态。
- `[DESIGN]` 管理员账号密码只通过管理命令创建，不写入 Git、镜像或日志；生产启用后台前必须接入独立管理员账号、MFA、RBAC、IP 限制和审计。
- `[CONFIRM]` Django Admin 的生产启用范围、管理员账号体系、权限矩阵、敏感字段展示和操作审计。

## 9. 运行安全

- `[DESIGN]` CI 做依赖、密钥、静态和迁移检查；生产最小权限、密钥环境注入、网络隔离、WAF/限流、备份加密和恢复演练。
- `[DESIGN]` 监控支付回调失败、余额不平、重复事件、异常退款/奖励/提现、登录风险、内容审核积压和第三方错误。
- `[DESIGN]` 任何安全事件都有 trace、影响范围、处置、复盘和用户通知流程。

## 10. 评价与收款提现安全

- `[DESIGN]` 评价接口必须校验订单归属、完成状态和评价窗口；匿名评价不得向公开接口、服务者接口或日志泄露评价用户身份。
- `[DESIGN]` 服务者评价管理接口只允许已开通服务者访问本人收到的评价；回复内容限长并防止重复回复。
- `[DESIGN]` 收款方式账号姓名和账号使用加密保存，数据库保存 HMAC 指纹用于查重，接口和日志只允许脱敏值。
- `[DESIGN]` 普通用户和服务者共用收款方式数据，但提现必须按 `PROVIDER_INCOME/REFERRAL_REWARD` 账户类型校验余额归属。
- `[DESIGN]` 提现、审核通过、拒绝、撤销和失败重试均使用幂等键、版本和状态日志；重复请求不得重复冻结、解冻或打款。
- `[DESIGN]` 当前 `PAYOUT_VERIFICATION_MODE=MOCK` 和 `PAYOUT_MODE=MOCK_MANUAL_REVIEW` 只用于开发测试；生产环境配置校验禁止模拟验证和模拟打款。
- `[DESIGN]` 管理员审核提现必须记录审核人、审核说明、状态前后值和渠道结果；真实支付、实名和打款凭据不得进入日志或 Git。

- `[DESIGN]` 资讯外部链接只允许 `http/https`，RSS 抓取拒绝本地、内网和非公网地址，并限制响应大小、超时和重试，防止 SSRF。
- `[DESIGN]` 外部资讯默认只保存摘要、图片 URL、原文链接和来源署名；未经版权确认不得保存全文或把远程图片下载为自有资源。
- `[DESIGN]` 资讯分享链接使用可配置公开域名和资讯公开 UUID，不携带认证 Token、用户 ID、手机号或精确位置。
- `[DESIGN]` 管理员资讯创建、编辑、发布、拒绝、删除、来源配置和同步必须受管理员权限保护并记录审计事件。

## 11. 开发测试密码登录安全

- `[DESIGN]` 开发测试密码登录只接受已经通过密码哈希保存的账号密码，禁止明文保存、返回或记录密码。
- `[DESIGN]` 未知账号、未设置密码和密码错误必须返回相同错误，避免账号枚举；密码校验失败不得签发令牌。
- `[DESIGN]` 生产环境即使误配置 `ENABLE_DEV_PASSWORD_LOGIN=true`，也必须由 `DJANGO_ENV=production` 强制关闭该接口。
- `[DESIGN]` 登录令牌继续使用不透明令牌、哈希存储、独立会话、刷新轮换和退出撤销，不得为开发登录降低令牌安全规则。
- `[DESIGN]` Swagger 的持久授权只保存在测试浏览器本地；浏览器共用、屏幕共享或导出 HAR 时不得暴露有效令牌。
- `[CONFIRM]` 正式密码登录的找回、限流、异常设备、双因素认证、凭证留存和安全审计尚未确认。
