# 自动化测试规范

## 1. 目标

- `[PRD]` 核心业务必须自动化覆盖正常、异常、边界、越权、重复请求和关键并发。
- `[DESIGN]` 测试优先保护身份权限、状态机、支付退款、账务、奖励、排期、敏感数据和迁移。
- `[DESIGN]` 每个任务结束必须报告测试命令、结果、未覆盖风险和人工验证项。

## 2. 测试分层

| 层级 | 工具 | 重点 |
|---|---|---|
| 单元 | pytest | 状态转换、金额/比例、政策快照、权限策略、校验器 |
| 服务/事务 | pytest-django | 应用服务事务、Outbox/Inbox、唯一约束、锁和补偿 |
| API | DRF APIClient/pytest | 请求格式、鉴权、越权、幂等、错误码、分页、OpenAPI |
| 集成适配器 | fake/stub + contract test | 支付、实名、IM、审核、推送、地图、存储 |
| 迁移 | Django migration executor | 空库建库、上一版本升级、回滚策略、约束和索引 |
| 并发 | 多事务/线程/隔离测试 | 重复支付、重复回调、重复完成、slot 占用、余额和奖励 |
| 回归/验收 | pytest + API | MVP 闭环、配置版本、数据保留和对账 |

## 3. 测试数据和隔离

- `[DESIGN]` 使用 Factory Boy/factories 构造最小有效业务对象；禁止复制生产数据和真实 PII。
- `[DESIGN]` 每个测试独立数据库事务或可重复 fixture；支付、IM、实名、审核、推送使用 fake adapter，失败场景可控。
- `[DESIGN]` 时钟、UUID、事件 ID、第三方单号可注入，保证快照和幂等测试确定性。
- `[DESIGN]` 测试密钥仅用于测试环境，不提交真实密钥；日志测试要断言敏感字段不出现。

## 4. 核心用例矩阵

### 账号身份

- 注册、验证码、登录、第三方绑定、退出、注销。
- 当前退出登录覆盖：撤销访问/刷新令牌、其他设备会话不受影响和无认证拒绝；并发刷新/退出使用用户行锁串行，仍保留专项并发测试缺口。
- 手机号登录当前覆盖：非法手机号、mock 验证码、自动注册、重复登录、错误/过期/已消费/超次数验证码、发送频率、幂等重放、令牌认证和刷新轮换。
- 首次身份选择首次成功、同值重复幂等、异值拒绝、未选择访问受限、服务者审核通过开通工作区。
- 游客、普通用户、服务者、客服、管理员、封禁用户的允许/拒绝场景。

当前服务者入驻实现必须覆盖：

- 首次身份选择成功、同值幂等、异值冲突和工作区返回。
- 申请正常提交、生活照数量配置、重复照片、身份证格式和敏感字段脱敏。
- 同一用户只有一个进行中申请、创建幂等、不同用户同键隔离和数据库唯一约束。
- `MOCK_PASSED` 状态、生产/配置禁用 Mock、未创建半成品申请。
- 普通用户访问管理接口越权、管理员通过/拒绝、拒绝原因、重复审核冲突和拒绝后重提版本冲突。

当前媒体上传实现必须覆盖：

- JPEG/PNG/WebP 正常上传、真实格式识别、尺寸/像素/大小边界和动态图片拒绝。
- EXIF/GPS 等元数据被移除，媒体读取使用正确的 Content-Type 和禁止公共缓存。
- 上传幂等重放、同键不同内容冲突、同用户同用途内容去重。
- 上传者读取成功、其他用户越权失败、管理员可读取。
- 服务者申请只能引用本人、正确用途、可用状态的媒体。
- `display_url` 无 Authorization 可加载、签名篡改返回 403、过期返回 410、10 分钟内接口复用地址。
- `/api/v1/users/me/` 返回当前申请的头像/生活照媒体摘要和 `display_url`。
- 后续公开资源必须测试审核/发布状态隔离，聊天媒体必须测试订单/会话关系隔离。

当前用户个人资料实现必须覆盖：

- 默认资料查询、城市/兴趣标签配置读取和安心用户预留字段。
- 昵称忽略大小写唯一、长度边界，年龄 18 到 40、性别白名单和签名长度限制。
- 兴趣标签代码校验、停用标签、重复标签、超过 5 个和整体替换。
- `expected_version` 冲突、相同内容重复修改、头像所有权和媒体用途校验。
- 所有请求和响应字段中文说明，资料接口不泄露账号敏感字段。

服务者资料和服务管理必须覆盖：

- 服务者权限、首次资料必填、昵称唯一、照片墙 3 到 6 张、类目/标签配置和媒体用途/所有权。
- 服务价格 `amount_minor` 和 `price_display`、价格/时长/名称/介绍/图集边界。
- 创建幂等、编辑版本冲突、DRAFT/REJECTED 编辑删除、PENDING 重复提交、审核、上架、下架和状态非法转换。
- 列表页码、状态筛选、summary 汇总、sold_count 只读和删除后不可查询。
- 管理员审核权限、拒绝原因、服务事件和 OpenAPI 参数说明。
- 管理员服务列表的全平台筛选、分页、关键词、服务者摘要和状态汇总。
- 首页服务者卡片的性别、最近 3 到 5 张照片、服务摘要、城市/类目筛选、游客限制和无动态时的照片回退。
- 首页只展示已上架服务者；无距离/评分/在线状态时明确返回 `null/UNKNOWN`。

服务者动态必须覆盖：

- 图文动态创建、发布即通过、修改、删除、幂等和版本冲突。
- 动态图片 1 到 9 张、封面、标签、可见范围和可选挂载服务。
- 挂载服务所有权和 `ONLINE` 状态校验。
- 公开列表/详情只返回已发布公开动态，草稿和已删除动态不可见。
- `REVIEW_REQUIRED` 模式下动态进入 `PENDING`，管理员通过后发布、拒绝后可重提。
- 动态事件、媒体 `display_url`、OpenAPI 参数说明和敏感数据脱敏。

钱包、预约订单、社交互动和评价必须覆盖：

- 管理员测试充值、用户禁止自主充值、余额流水和幂等。
- 余额不足、重复支付、重复退款、余额支付成功和取消退款释放时段。
- 服务者时段重叠、时长匹配、创建订单锁定和取消释放。
- 订单状态机、服务者接单/拒绝/履约、用户确认和版本冲突。
- 关注、收藏、点赞、评论的唯一性、计数、越权删除和重复操作。
- 订单完成后评价、7 天窗口过期、一个订单一次评价、匿名评价和服务者回复。
- 动态上下滑动的前驱/后继顺序、首尾边界、筛选上下文、不可见动态排除和非法排序拒绝。
- 动态类目从配置接口读取；推荐、同城、关注 Tab 的元信息、筛选和未开放状态正确。

### 服务者服务排期

- 认证/资料审核通过、拒绝重提、停用/恢复。
- 服务价格快照、上下架、地点规则、类目配置。
- 同一 slot 单占用、并发占用、取消释放、改期、超时释放、容量边界。

### 订单履约

- 下单成功、重复下单幂等、支付前取消、支付后待接单。
- 服务者本人接单/拒单/改期，越权操作被拒绝。
- 双方打卡、服务完成、用户确认、24 小时自动完成、迟到/未履约/协商取消。
- 所有状态转换均断言 `order_status_logs`、版本、权限和快照。

### 支付退款资金

- 正常支付、支付失败、重新支付、重复支付请求、回调验签失败、金额不符、乱序/重复/迟到回调。
- 全额/部分退款、退款失败恢复、累计退款上限、重复退款回调。
- 佣金、服务者收入、钱包流水、冻结/解冻、提现申请/审核/打款/失败反向流水。
- 余额由流水重放相等；并发入账不重复；对账差异被发现。

### 邀请奖励

- 无邀请、有效一级邀请、自邀请、重复绑定、同人/同设备风险。
- 比例快照支付时锁定，历史订单不受政策修改影响。
- 完成奖励、全额退款取消、部分退款重算冲减、冻结/解冻/补发/取消、提现。
- `A→B→C` 只奖励 B；一订单一条奖励；重复结算不重复入账。

### 内容 IM 安全

- 动态/资讯发布、审核、拒绝、删除、举报、评论/点赞/收藏/关注权限。
- 订单会话解锁、支付前不可私信、取消/退款/完成后的保留策略。
- 敏感内容/消息审核、拉黑、报警、行程分享和位置脱敏。
- 越权读取订单、聊天、钱包、认证和后台导出被拒绝并留安全日志。

## 5. 并发和事务要求

- `[DESIGN]` 对“支付回调、退款回调、完成、奖励结算、钱包入账、slot 锁定、归因绑定”做重复和并发测试。
- `[DESIGN]` 断言数据库唯一约束、行锁/乐观锁和事务回滚；不能只测试 HTTP 返回。
- `[DESIGN]` 测试事件乱序、重复、失败重试、死信和人工重放；消费端必须幂等。

## 6. 迁移和兼容

- `[DESIGN]` 每次迁移从空数据库执行，并从上一发布 schema 升级；验证数据、约束、索引和 Django 检查。
- `[DESIGN]` 旧 API 版本/旧客户端字段兼容要有契约测试；破坏性变更需迁移窗口和回滚方案。
- `[DESIGN]` 金额、状态、政策和审计数据迁移必须抽样核对数量、合计、状态分布和唯一性。

## 7. 质量门槛

- `[DESIGN]` 新增核心模块必须有单元和服务测试；资金/状态/权限模块分支覆盖率目标不低于 95%，项目整体不低于 85%。
- `[DESIGN]` Ruff、pytest、迁移检查、OpenAPI 校验、依赖/密钥扫描全部通过后才可合并。
- `[DESIGN]` 不允许删除、跳过或弱化安全/资金测试来规避失败；确需变更测试必须说明业务原因和替代验证。

### 7.1 注释与接口文档检查

- `[DESIGN]` 自动检查所有业务模型表和字段是否具备中文表备注和 `db_comment`。
- `[DESIGN]` 自动检查业务服务、认证、加密和存储模块的模块、公共类和公共函数是否有中文说明。
- `[DESIGN]` 自动检查 API serializer 字段是否有中文 `help_text`，并验证 OpenAPI 参数说明可见。
- `[DESIGN]` 备注迁移必须应用到空库和现有开发库，不允许手工修改数据库备注。

手机号认证测试还必须断言：响应不返回完整手机号、验证码和令牌不写入日志、`user_auths` 唯一约束可阻止重复绑定、生产配置不能启用验证码 mock。

资讯补充测试要求：

- 资讯创建、编辑、发布、拒绝、逻辑删除和版本冲突。
- App 列表、详情、类目、分享域名和分享字段隐私。
- `NEWS` 收藏只能指向已发布公开资讯，重复收藏幂等。
- RSS 同步的来源去重、摘要边界、部分失败计数和重复执行。
- 新模型、迁移、中文表/字段备注和 OpenAPI 资讯契约。

搜索补充测试要求：

- 综合搜索同时命中服务者、动态和资讯，分类搜索只返回公开内容，并验证总数、预览数量、游标分页和空关键词拒绝。
- 搜索词兼容分解、忽略大小写、空白合并和长度边界；手机号、身份证、邮箱、URL、银行卡等敏感词不进入聚合。
- 搜索统计按自然日和规范化词唯一累加，不保存用户、设备、IP 或原始请求；并发首次聚合不重复。
- 热门词按窗口计算、人工置顶优先、`ACTIVE/HIDDEN/BLOCKED` 过滤和稳定排序正确。
- 管理员创建相同配置幂等、不同配置冲突、非管理员越权拒绝；修改验证 `expected_version` 和并发版本冲突。
- 新增搜索模型迁移、中文表/字段备注、OpenAPI 搜索请求响应模型和敏感信息不返回。

开发测试密码登录补充要求：

- 正确账号密码返回标准访问/刷新令牌，Bearer 令牌可以访问 `users/me`。
- 未知账号、未设置密码和错误密码统一返回 `AUTH_INVALID_CREDENTIALS` 且不创建令牌。
- 账号状态非 `ACTIVE` 时拒绝登录；生产环境和关闭开关时接口返回 404。
- `Idempotency-Key` 重放复用令牌，同键不同密码返回冲突。
- 响应、异常和日志测试不得出现明文密码；OpenAPI 标记 `password` 只写并提供中文说明。
